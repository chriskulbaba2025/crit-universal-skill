# Design Principles

1. **Context before command.** Problem modeling precedes solution generation.
2. **Information gain over interrogation.** Interview questions exist only to resolve material uncertainty.
3. **Anti-goals are requirements.** What must not happen can reshape the solution as much as the desired outcome.
4. **Role includes authority.** Expertise without ownership boundaries encourages overreach.
5. **One problem model, then iteration.** Do not restart from scratch every time feedback arrives.
6. **Approved work is immutable by default.** Revision is surgical, not regenerative.
7. **Top-down decomposition.** Stabilize parent decisions before producing subordinate detail.
8. **Fluency is not compliance.** Every hard constraint receives an explicit verification pass.
9. **Evidence outranks confidence.** Semantic scoring improves review discipline but never replaces source, test, or tool evidence.
10. **Portability lives in semantics.** Platform adapters may change loading mechanics, not the core reasoning order.
